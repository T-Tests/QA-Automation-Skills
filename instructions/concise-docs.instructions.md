# Concise documentation

- Open with what the thing does and why it exists, in one sentence.
- Use present tense, second person, active voice.
- Use a table or bullets instead of a paragraph when listing more than two parameters, steps, or options.
- Don't repeat a fact already covered elsewhere; link to it.
- Every code sample must run as written. No unexplained placeholders.
- If one concept needs more than about 150 words, split it under subheadings.
- Document only behavior you verified in the code. Mark unknowns as TODO; don't guess.
- Update docs in the same change that alters the behavior.
- Explain why, not what the code already says.
- Never put secrets, real credentials, or internal URLs in docs or examples.
- Diagrams: use Mermaid in a fenced block, and include only components that exist in the code.
